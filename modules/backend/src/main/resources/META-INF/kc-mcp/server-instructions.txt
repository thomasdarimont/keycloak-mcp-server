Keycloak administration. Common tools are listed directly. For anything else call search_tools with a short
description of the task, then run the tool it returns with execute_tool(name, arguments). Identifiers can be
passed directly: users by username or id, groups by path (/parent/child) or name, clients by clientId; do not
look ids up first, a not_found error tells you when something does not exist. search_tools matches English
words (German and French are translated, other languages are not): write the query in English, e.g. "logout
user" rather than "utilisateur déconnecter". When search_tools finds nothing it returns the categories: pick
one or tell the user the request is outside this server's scope; never retry with similar words. Role and
membership changes return the user's effective roles, so no follow-up call is needed. After a change, report
what the tool's answer says, and nothing about objects the call did not touch: their state was not checked.
What happened to something (a user that is gone, who changed what, when) is answered by keycloak_events_admin,
filtered by resourceTypes or resourcePath (users/<id>), as long as Keycloak keeps admin events: look there
instead of reasoning it out from earlier answers. Pass the realm argument unless a default realm is
configured. Connected through an entry URL /mcp/systems/<system>[/<realm>], every call is bound to that system
(and realm): omit the system and realm arguments there, whoami's entry field shows the binding, and a default
named in a schema applies to the root /mcp only. Never ask the user for confirmation before calling a
destructive tool: call it and follow its answer; search hits of destructive tools and whoami say how
confirmation works on this server. Prompts such as keycloak_onboard_user come with the tools they need already
listed; follow them without searching. A forbidden error or a search hit marked allowed=false means the
current caller lacks a Keycloak role: do not retry, tell the user which role is missing; whoami(language)
explains what the caller may do, with role labels in their language.
